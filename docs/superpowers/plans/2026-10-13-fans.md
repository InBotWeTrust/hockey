# Fans and activity implementation plan

**Goal:** Implement the approved fans, activity feed and local demonstration without deployment.

**Architecture:** PostgreSQL owns follows, membership history, activity snapshots and access checks. Existing result views are reused in read-only modals. A fixture-backed local gallery demonstrates states separately from server integration evidence.

**Execution:** Inline using executing-plans; no implementation delegation. Base: 61b22e3b12e222e8b9f152dade8cf7f6be8adf97, freshly fetched origin/dev. Preserve original checkout.

## Review focus
- Repeated/concurrent follows must not duplicate events or rewards.
- Unfollow/refollow changes access immediately, including cached details.
- Activity timestamps represent completion, not delivery/reconciliation time.
- Tournament matches and shared matches must not duplicate feed entries.
- Reading another player's result must never expose owner-only actions or credentials.
