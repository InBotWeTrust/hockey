# Очко и армрестлинг Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Работать самостоятельно в этом чате; делегирование не разрешено текущими инструкциями проекта.

**Goal:** Добавить Очко с Григорием на звёзды и бесплатный армрестлинг с Олегом, включая онлайн, с переиспользованием существующих игровых сценариев бара.

**Architecture:** Две последовательные поставки на общем механизме матчей: сначала Очко, затем армрестлинг. Правила и воспроизводимый расчёт находятся в game-core; скрытая колода, баланс и окончательное состояние принадлежат серверу. Клиент переиспользует лобби, приглашения, готовность, меню, подсказки, правила и результаты; добавляет только специфические поля и управление.

**Tech Stack:** TypeScript, pnpm, Vitest, PostgreSQL, Fastify, React, SVG/CSS; существующая система изображений и GitHub Actions.

**Spec:** [2026-10-16-ochko-armwrestling-design.md](../specs/2026-10-16-ochko-armwrestling-design.md)

## Global Constraints

- Игроки: Григорий – Очко со ставкой, Олег – бесплатный армрестлинг; обе игры онлайн бесплатно.
- Одна активная сессия бара, включая карты. Онлайн: принятие сразу на поле, «Готов» на поле, 5 секунд после готовности обоих. С персонажем без готовности.
- Очко: колода 36, туз 11, валет 2, дама 3, король 4; 40 секунд каждому на раздачу без анимаций выдачи карт. Оба стартовых туза старше обычного 21.
- Предложение Григория: 1…min(30, баланс). Встречная ставка: 1…баланс, без ограничения 30. Победа возвращает 2X, ничья X. Сдача теряет ставку.
- Армрестлинг: два пальца, три положения кисти, одна выносливость; 60 секунд. Полное бездействие: предупреждение через 5 секунд, поражение через 10 секунд.
- Общий UI и тексты ошибок переиспользуются. Нет отдельной модалки готовности или нижней плашки ошибки.
- Старые матчи и истории сохраняются. Версия правил закреплена за матчем. Хоккейный расчёт не меняется.
- Читать scoped AGENTS из основного checkout, если их нет в рабочем. Проверить свежесть origin/dev перед веткой. Основной checkout с посторонними изменениями не трогать.
- Тесты БД и Redis только на подтверждённых выделенных тестовых целях. Не создавать и не менять учётные данные.
- Изображения с утверждёнными референсами, без надписей; WebP с новым версионированным URL. Production исключён, dev только по отдельному указанию пользователя.

## Review Focus

1. Две вкладки одновременно подтверждают ставку или покупают другой предмет: баланс не отрицательный, одна партия, один дебет. Тест задачи 2.
2. Повторный ответ или завершение матча после рестарта: выплата не повторяется и не теряется. Тест задачи 2.
3. Одновременные действия двух игроков и запоздалый ответ: чужой ход не откатывает свой, скрытая колода не утекает. Тесты задач 3 и 6.
4. Уход вкладки с зажатым пальцем или потеря pointercapture: давление прекращается, захват не зависает. Тесты задач 5 и 7.
5. Изображение загрузилось поздно или экран стал ниже из-за панели браузера: поле, меню и органы управления не перекрываются; ход не сбрасывается. Проверка задачи 9.
