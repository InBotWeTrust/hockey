# Доступность соперников для обычных дуэлей

**Статус:** поведение согласовано пользователем 2026-09-23; документ ожидает проверки перед планированием реализации.

## Цель и границы

Игрок видит только подходящих для выбранных форматов соперников в быстром выборе и поиске. В двух вариантах профиля и модалке выбора формата причины недоступности понятны до отправки вызова. Турнирные дуэли не затрагиваются. Серверная проверка при создании вызова сохраняется как окончательная защита от гонок.

## Единое решение о доступности

Сервер вычисляет доступность пары игроков по каждому из трёх форматов: «Экспресс», «Микс», «Классика». Учитываются дневной, недельный и месячный общие лимиты обоих игроков, месячный лимит формата каждого, открытые дуэли и исходящие приглашения, а также существующие игровые и плей-офф блокировки. Для недоступного формата ответ содержит машинную причину и сторону (`self` либо `opponent`); клиент показывает русскую причину, не выводя внутренний код. Если причины конкурируют, приоритет — блокировка текущего игрока, затем соперника, затем ограничение исходящих вызовов.

Существующий `/duel/amateur/challenge/availability` становится источником истины для профилей и модалки. Он возвращает общий флаг доступности как `true` только при наличии хотя бы одного доступного формата. `/duel/amateur/opponents` использует тот же расчёт, возвращает доступность по форматам для каждого кандидата и исключает тех, с кем нельзя сыграть ни в одном запрошенном формате. Параметр выбранных форматов допускает один или несколько значений; без параметра используются все три для совместимости с другими клиентами. Фильтрация выполняется до применения итогового ограничения числа отображаемых кандидатов, чтобы закрытые лимитами игроки не вытесняли подходящих.

## Поведение экранов

В быстром выборе и поиске на вкладке дуэлей запрос привязан к текущему выбранному формату. Смена формата обновляет список. Соперник, доступный только в другом формате, в текущем списке не показывается. При смене формата уже выбранный соперник сохраняется лишь если новый формат доступен обоим; иначе выбор сбрасывается с понятным пояснением.

В `UserProfileSheet` и `UserProfileScreen` доступность запрашивается до нажатия «Вызвать на дуэль». Если нет ни одного доступного формата, кнопка выглядит недоступной, но остаётся нажимаемой: нажатие показывает конкретную причину во всплывающем уведомлении. При загрузке или ошибке проверки интерфейс не изображает достоверную доступность: показывает состояние ожидания или повторную попытку.

`DuelChallengeModal` выбирает первый доступный формат после получения данных, не оставляет выбранным заблокированный формат и показывает причину на каждой заблокированной карточке. Если все форматы недоступны, отправка вызова невозможна. При изменении лимита после открытия экрана ошибка сервера обновляет доступность и выводит понятное сообщение.

## Уведомление и доступность

Уведомление о невозможности вызова использует визуальный контейнер `achievement-reward-toast`, который применяется при начислении наград за задания: те же положение, ширина, фон, типографика и анимация. Текст отличается по смыслу: краткий заголовок и конкретная причина, без иконок награды. Элемент имеет `role="status"`; кнопка вызова сохраняет клавиатурную доступность. Причина заблокированного формата доступна не только через `title` при наведении, но и видимым текстом в модалке.

## Проверки

- Сервер: доступность по каждому формату для обеих сторон; общий, форматный и открытый лимиты; сочетание с игровой/плей-офф блокировкой; выбранные форматы и фильтрация до `limit`; повторная проверка при отправке вызова.
- Клиент: быстрый выбор и поиск исключают неподходящих, обновляются при смене формата; оба профиля показывают заблокированную кнопку и тост; модалка выбирает первый доступный формат и объясняет каждый заблокированный.
- Рендер в локальном браузере: профиль из обоих входов, поиск, быстрый выбор, узкий экран, клавиатурное управление и визуальное сходство тоста с уведомлением награды.

Интеграционные тесты сервера запускать только в изолированной тестовой БД: они не должны сбрасывать локальную БД игры.
